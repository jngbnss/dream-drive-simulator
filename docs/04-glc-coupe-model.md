# STEP 04. Mercedes-Benz GLC Coupé (참고 차량) 구현

> 상태: **설계 초안 · 오피스아워 권장안 적용됨 · 구현 대기**

## 1. 목표
- GLC Coupé의 비율과 특징(쿠페형 루프라인, 넓은 그릴, 수평형 테일램프)을 **참고한** 외관 모델
- 도장 PBR 재질(클리어코트, 메탈릭 플레이크), 유리, 크롬, 고무
- 헤드라이트·테일램프(발광 재질 + 주행 시 스폿라이트)
- 실내: 대시보드, 스티어링 휠(조향 입력과 연동 회전), 디지털 계기판(실시간 속도·RPM을 CanvasTexture로 표시)
- 차량 색상 선택(쇼룸 UI)
- 외부 GLB 모델 교체 기능(설정 파일/드래그 앤 드롭)

사용자 경험: 쇼룸에서 "이건 GLC 쿠페네" 싶은 차를 원하는 색으로 바꿔 보고, 운전석에 앉으면 계기판 바늘이 실제로 움직입니다.

## 3. 구현 설계
- `vehicle/VehicleVisual.ts`: GLB 로드, 노드 이름 규칙으로 휠·핸들·도어·라이트 바인딩
- **GLB 노드 명명 규칙**: `Body`, `Paint`(색상 변경 대상), `Wheel_FL/FR/RL/RR`, `SteeringWheel`, `Dashboard_Screen`, `Headlight_L/R`, `Taillight_L/R`, `Seat_Driver_EyePoint`(빈 객체)
- `vehicle/PaintSystem.ts`: 프리셋 색상(옵시디언 블랙, 폴라 화이트, 셀레나이트 그레이, 스펙트럴 블루 계열 — 명칭은 "참고 색상"으로 표기)
- `ui/ShowroomPanel.ts`: 색상 선택, 탑승 버튼
- 모델 교체: `?model=URL` 또는 로컬 파일 드래그(브라우저 메모리에서만 사용, 업로드 없음) — 명명 규칙 미준수 시 자동 추정 + 경고

### 제작 전략 (단계적)
1. **v0 플레이스홀더**: Blender에서 블록 형태(로우폴리 2~5k tris)로 빠르게 제작 → 파이프라인 검증
2. **v1 디테일**: 하드서피스 모델링(외관 목표 60~100k tris), 실내 20~40k tris
3. LOD: LOD0(쇼룸), LOD1(주행 3인칭), LOD2(교통 차량 재사용)

## 4. 구현 순서

- [ ] 3. HDRI 환경맵 + 도장 재질
- [ ] 4. 쇼룸 무대(턴테이블, 반사 바닥)
- [ ] 5. 색상 선택 UI
- [ ] 6. 실내 + 핸들 회전 + 계기판 CanvasTexture
- [ ] 7. 라이트(발광 + 야간 스폿, 그림자는 비활성)
- [ ] 8. 외부 GLB 교체
- [ ] 9. v1 디테일 모델(병행 장기 작업)

## 5. 예상 문제
| 위험 | 대응 |
|---|---|
| **상표·디자인권** | 엠블럼·로고 미사용, "GLC Coupé 참고" 문구, 외부 공식 모델은 로컬 교체 전용 |
| 모델 제작 시간 과다(가장 큰 일정 위험) | v0로 다음 단계를 막지 않게 하고 v1은 병행 |
| 쇼룸 품질 부족 | HDRI, 클리어코트, 앰비언트 오클루전 베이크, 후처리(STEP 06) |
| 모델 용량 증가 | Meshopt + KTX2, 목표 차량 GLB ≤ 5MB |
| AI 생성 모델 품질/라이선스 | 소품에만 실험 사용, 결과 비교 기록 |

## 6. 완료 기준
- 쇼룸에서 색상 변경, 360도 감상, 탑승 후 실내에서 핸들·계기판이 입력과 동기화
- 압축된 차량 GLB ≤ 5MB, 쇼룸 60 FPS(기준 PC)

## 7. 테스트
- 기능: 색상 5종 전환, 외부 GLB(예: Khronos 샘플 모델) 교체, 휠 회전·조향 방향 확인
- 성능: 모델 용량(원본/압축), 로딩 시간, 쇼룸 Draw Call
- 품질: 지인 3명에게 "어떤 차로 보이는지" 블라인드 질문
