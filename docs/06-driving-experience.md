# STEP 06. 주행 몰입감 개선

> 상태: **설계 초안 · 오피스아워 권장안 적용됨 · 구현 대기**

## 1. 목표
- 엔진음(RPM·부하 연동), 타이어 스키드, 브레이크, 바람 소리
- 가속·감속 피드백: 카메라 관성, FOV, 미세 진동
- 서스펜션 반응·코너링 롤·제동 피치(시각 차체를 물리값으로 기울이기)
- 날씨(맑음/비: 노면 마찰 감소, 빗방울 파티클, 젖은 노면 반사), 주간·야간·노을
- 조명과 그림자(CSM 또는 차량 주변 그림자 카메라 추적), 야간 헤드라이트
- HUD 개선(아날로그 속도계, 기어, 미니맵, 랩 델타)
- 레이싱 휠/게임패드 매핑 프로필

사용자 경험: 눈을 감아도 가속하는 게 들리고, 밤의 도심을 헤드라이트를 켜고 달리는 분위기.

## 2. 기술 및 오픈소스
| 기술 | URL | 라이선스 | 선택 이유 | 대안 |
|---|---|---|---|---|
| Web Audio API | 웹 표준 | — | 실시간 피치·크로스페이드 | Tone.js |
| 엔진 샘플 | freesound.org 등 | 개별 CC 라이선스 ⚠️ | 현실감 | 절차적 합성 |
| postprocessing | https://github.com/pmndrs/postprocessing | zlib | Bloom, SMAA, 톤매핑 | three EffectComposer |
| Three CSM (addons) | three.js | MIT | 넓은 맵 그림자 | 차량 추적 단일 그림자 |
| Gamepad API | 웹 표준 | — | 패드·휠 입력 | — |

## 3. 구현 설계
- `audio/EngineAudio.ts`: RPM 대역별(아이들/저/중/고) 루프 4개, 게인 크로스페이드 + playbackRate, 부하(스로틀)에 따른 on/off-load 샘플 블렌드
- `audio/AudioSystem.ts`: 사용자 첫 클릭 시 AudioContext resume(브라우저 자동재생 정책)
- `vehicle/BodyMotion.ts`: 횡가속·종가속 → 시각 차체 롤/피치(스프링 감쇠)
- `world/Weather.ts`, `world/TimeOfDay.ts`: 하늘·조명·안개·마찰 계수
- `ui/HUD.ts` 리팩터링

## 4. 구현 순서
- [ ] 1. AudioSystem + EngineAudio (샘플 라이선스 확인 → 없으면 합성)
- [ ] 2. 스키드·브레이크 사운드
- [ ] 3. BodyMotion
- [ ] 4. TimeOfDay(주간/노을/야간) + 헤드라이트
- [ ] 5. Weather(비) + 마찰 연동
- [ ] 6. 그림자 전략 비교(CSM vs 추적 그림자) → 측정 후 선택
- [ ] 7. 후처리(Bloom, SMAA) 품질 옵션
- [ ] 8. HUD 개선, Gamepad 매핑
- [ ] 9. 블라인드 비교 테스트(STEP 05 빌드 vs STEP 06 빌드)

## 5. 예상 문제
| 위험 | 대응 |
|---|---|
| 엔진 샘플 확보·라이선스 | CC0 우선, 출처 기록, 없으면 합성 |
| 후처리로 FPS 하락 | 품질 프리셋(Low/Med/High), 자동 감지 |
| 레이싱 휠마다 축 매핑이 다름, 포스 피드백은 브라우저 지원 제한 ⚠️ | 매핑 프로필 + 캘리브레이션 화면, FFB는 범위 외 |
| 비/야간에서 시야 불량 | 밝기 옵션 |

## 6. 완료 기준
- 사용자 3명 이상이 STEP 05 대비 몰입감이 좋아졌다고 평가(5점 척도 평균 +1 이상)
- High 프리셋에서 기준 PC 60 FPS, Low 프리셋에서 내장 GPU 노트북 30 FPS 이상

## 7. 테스트
