# STEP 07. AI 및 고급 기능

> 상태: **설계 초안 · 오피스아워 권장안 적용됨 · 구현 대기**

## 1. 목표
- **교통 차량**: 도로 그래프 위 차선 추종, 차간 거리 유지, 신호 준수, 교차로 회전 — *규칙 기반*
- **보행자**: 인도 경로 추종, 횡단보도 신호 대기 — *규칙 기반*
- **자연어 목적지 선택 (핵심 AI 기능)**: "남산 쪽으로 가고 싶어", "한강 보이는 데 드라이브" → 맵 POI → 경로 → 미니맵 경로 표시
- **음성 드라이빙 가이드**: "300m 앞에서 우회전입니다" (템플릿 + Web Speech TTS), 선택적으로 LLM이 주변 랜드마크 설명 생성
- **AI 활용 전후 비교**: 규칙 기반 파서 vs LLM의 정확도·지연·비용

> 원칙: AI는 **자연어 이해**처럼 규칙으로 풀기 어려운 문제에만 씁니다. 교통·보행자는 고전 알고리즘이 더 정확하고 가볍습니다.

## 3. 구현 설계
- `ai/traffic/TrafficSystem.ts`: 차량 풀(최대 N대, 인스턴싱), 플레이어 주변에서만 스폰/디스폰, 원거리는 운동학 이동(물리 없음), 근거리만 키네마틱 바디로 충돌
- `ai/traffic/IDM.ts`: 순수 함수(단위 테스트)
- `ai/pedestrians/PedestrianSystem.ts`: 인도 폴리라인 추종
- `ai/guide/DestinationParser.ts` 인터페이스
  - `RuleBasedParser`: 키워드·별칭 사전(오프라인, 항상 사용 가능)
  - `LlmParser`: 프록시 호출 → `{ poiId, confidence, reason }` 스키마 검증, 실패 시 RuleBased 폴백
- `ai/guide/Navigator.ts`: A* 경로, 다음 기동 계산
- `ai/guide/VoiceGuide.ts`: 안내 문장 템플릿 + TTS
- `proxy/` (별도 배포): Worker 코드, 요청 횟수 제한, 허용 도메인 검사

## 4. 구현 순서
- [ ] 1. IDM + 차선 추종 교통 차량(10대 → 50대)
- [ ] 2. 신호 준수, 교차로 회전
- [ ] 3. 보행자(간단 버전)
- [ ] 4. POI 데이터(맵별 20~50곳, 별칭 포함)
- [ ] 5. **평가 데이터셋**: 한국어 목적지 발화 100문장(구어체·오타·간접 표현 포함) + 정답 POI
- [ ] 6. RuleBasedParser + 평가(베이스라인)
- [ ] 7. LLM 프록시 + LlmParser + 평가
- [ ] 8. Navigator + VoiceGuide
- [ ] 9. 비교 결과 기록, 기본값 결정

## 5. 예상 문제
| 위험 | 대응 |
|---|---|
| API 키 노출 | 클라이언트에 키를 두지 않음, 프록시 + 레이트 리밋 + 허용 Origin |
| LLM 비용·남용 | 일일 한도, 짧은 프롬프트, 응답 캐시 |
| LLM 지연(수백 ms~수 초) | 정차 중/메뉴에서만 입력, 로딩 표시 |
| 환각(맵에 없는 장소) | POI 목록을 프롬프트에 제공하고 ID만 선택하게 함, 스키마 검증 |
| 교통 차량 수 증가로 성능 저하 | 근거리만 물리, 인스턴싱, 업데이트 주기 분산 |
| 한국어 TTS 음성 미지원 브라우저 | 자막 안내 폴백 |

## 6. 완료 기준
- LLM 파서가 평가셋에서 규칙 파서보다 정확도가 **유의미하게 높고**(목표 +20%p), p95 지연 2초 이하, 1회 비용 기록
- 교통 차량 50대 + 보행자 30명에서 기준 PC 60 FPS
- 프록시가 없을 때도 규칙 파서로 기능 동작
